# Superwriter v3–v6: quality controls, verse forms, examples, custom profiles

**Date:** 2026-08-29
**Status:** approved design — implementation pending
**Ships as:** four PRs / releases, in order — A (v3), D (v4), C (v5), B (v6)

## Context

`superwriter` is a stateless Claude skill (shipped v1, v2) that writes in a named author's
voice or a functional register, in generate or transform mode. It decomposes style into ten
craft dimensions (`superwriter/references/craft-dimensions.md`) and holds one profile per
voice under `references/authors/` (12) and `references/registers/` (6). `SKILL.md` routes;
`transform.md`, `analysis.md`, `blending.md` cover the non-generate paths. CI
(`.github/workflows/skill.yml`) runs `scripts/validate_skill.sh`, packages
`superwriter.skill`, and publishes a GitHub Release on a `v*` tag. `main` is branch
protected: PR + passing `validate` check + linear history required.

This spec covers four independent upgrades. They are sequenced by leverage (value ÷
per-request token cost), not by dependency — only C benefits from D landing first (so its
examples can cover the forms).

## Invariants — every sub-project preserves these

1. **Per-request token budget.** A normal generate/transform request still loads exactly
   `SKILL.md` + `craft-dimensions.md` + one profile (form requests add
   `form-dimensions.md`). New per-request content lands only in `SKILL.md` and is justified
   line by line. Current worst case ≈ 8.4 KB; **ceiling for this roadmap: 10 KB**. Each PR's
   verification recomputes the worst case and fails the plan if it breaches.
2. **Statelessness.** No files are written to the user's account at runtime. Anything
   "saved" is returned to the user as text with manual install steps.
3. **No reproduced passages; no fabricated attribution.** Unchanged. Sub-project C composes
   only original passages. Sub-project B forbids third-party named profiles.
4. **Parallel structure is load-bearing.** Every profile — author, register, form, custom —
   keeps the same ordered shape: `# Title`, `**Furthest from neutral:** …`, dimension
   bullets in fixed order, `**Writing it:** …` closing on the caricature failure.
5. **CI is the gate.** Every structural rule below is enforced in `validate_skill.sh`.
   Generated files (`references/voices.md`) are rebuilt in CI and `git diff --exit-code`-ed.

## Sub-project A — Quality & control → v3

Three small changes, no new reference category. Highest leverage.

### A1. Output self-check

New section in `SKILL.md`, placed after `## Output`:

```
## Before returning

Read the draft once against the profile:
- Did you lean on the surface tics named in the caricature-failure line? Cut them.
- Are the dimensions that should sit ordinary actually ordinary, or did you push all
  of them? Pull the non-signature dimensions back toward neutral.
- Transform mode: run the content check in transform.md — every claim, fact, name,
  number, and the argument's order still present.
```

≈ 55 words / ≈ 0.35 KB per request. No new file.

### A2. Strength dial

Command grammar (updated in `## Modes` and `## Commands`):

```
/superwriter <voice> [light|medium|strong] — <brief>
[pasted text] /superwriter <voice> [light|medium|strong]
```

New section in `SKILL.md`:

```
## Strength

light · medium (default) · strong — how far to push the signature dimensions.
- light  — one signature dimension, gently. Reads as "influenced by," not pastiche.
- medium — the two or three signature dimensions pushed. Default.
- strong — signature dimensions pushed hard, still stopping short of the caricature failure.
Non-signature dimensions stay near neutral at every strength.
```

≈ 50 words / ≈ 0.3 KB per request. No parsing needed — the model reads the token.

### A3. Generated voices index + richer `list`

- **New generated file** `superwriter/references/voices.md`: a table of every voice (authors
  and registers now; forms from v4; custom from v6) with its `**Furthest from neutral:**`
  phrase copied verbatim from the profile's second line, under a
  `<!-- generated by scripts/build_index.sh — do not edit -->` header.
- **New `scripts/build_index.sh`**: scans `superwriter/references/{authors,registers,forms,custom}/*.md`
  (skipping `README.md`, tolerating categories that do not exist yet — `forms/` arrives in
  v4, `custom/` in v6), extracts the `# Title` and the `**Furthest from neutral:**` line,
  writes `references/voices.md` sorted by category then name.
- `SKILL.md` routing table gains a row: `references/voices.md | /superwriter list`. `list`
  reads only this file.
- `validate_skill.sh`: run `build_index.sh` to a temp file, `diff` against the committed
  `references/voices.md`; any mismatch fails with "voices.md is stale — run
  scripts/build_index.sh". The existing "`references/` has exactly 4 top-level `.md`"
  assertion is replaced by "all required files present (`craft-dimensions`, `transform`,
  `analysis`, `blending`) and no top-level `.md` outside that set plus the allowed generated
  file `voices.md`".

Per-request cost: **zero** (read only on `/superwriter list`).

### A — files touched

| File | Change |
|---|---|
| `superwriter/SKILL.md` | `## Before returning`, `## Strength`, grammar, `voices.md` routing row |
| `superwriter/references/voices.md` | new, generated |
| `scripts/build_index.sh` | new |
| `scripts/validate_skill.sh` | index-drift check |
| `README.md` | Strength section, `list` behaviour, dev note on the index |

### A — verification

- `bash scripts/validate_skill.sh` passes.
- `bash scripts/build_index.sh && git diff --exit-code superwriter/references/voices.md` clean.
- Worst-case per-request footprint recomputed, ≤ 10 KB (expected ≈ 9.1 KB).
- Read-through: `/superwriter Hemingway strong — …` vs `/superwriter Austen light — …` differ
  visibly in push; `/superwriter list` prints signatures.

## Sub-project D — Verse forms → v4

New category for verse. The ten craft dimensions are prose-oriented, so forms get a small
companion dimension file loaded only for form requests.

### D1. `references/form-dimensions.md` (new)

Companion to `craft-dimensions.md`. Axes, in fixed order:

| # | Dimension | Attend to |
|---|---|---|
| 1 | Meter | Base foot and line length; how strictly kept; where substitution is licensed. |
| 2 | Lineation | Where lines break and why; the line as a unit of sense vs. of sound. |
| 3 | Rhyme | Scheme; exactness (full / slant / none); structural vs. ornamental function. |
| 4 | Stanza | Size; whether the argument maps to stanza units; use of white space. |
| 5 | Enjambment vs end-stop | Ratio, and what a run-on line does to pace and emphasis. |
| 6 | Turn | The volta, refrain, or structural pivot the form expects, and where it falls. |
| 7 | Sound | Alliteration, assonance, consonance — density relative to the form's norm. |
| 8 | Compression | What gets cut to fit; inversion and ellipsis under metrical pressure. |

Selection, figurative habit, and diction carry over from `craft-dimensions.md` unchanged and
are not restated here.

### D2. `references/forms/` (6 new)

`sonnet.md`, `blank-verse.md`, `heroic-couplet.md`, `ballad.md`, `free-verse.md`,
`haiku.md`. Same profile shape as the other categories, written against the eight form
dimensions (fixed order) plus the three carried-over craft axes. Each closes on its
caricature failure, e.g.:

- **sonnet** — filler syllables to hit the count; a forced, epigram-hunting final couplet.
- **free verse** — chopped prose with line breaks at random; no rhythmic reason for the lineation.
- **haiku** — 5-7-5 syllable-counting with no cut (*kireji*) and no concrete seasonal grounding.

### D3. Routing

- `SKILL.md` `## Voices` gains a **Forms** subsection listing the six.
- Rule: a form request loads `craft-dimensions.md` + `form-dimensions.md` + one
  `forms/<name>.md`. ≈ +2 KB, **only on form requests**.
- Generate ("write this as a Shakespearean sonnet") and transform ("put this argument in
  heroic couplets") both apply. Transform note added: line and stanza counts will change;
  meaning stays fixed; flag when the form cannot hold the content without cutting.
- Blend: form + author is allowed ("a ballad with Poe's acceleration"). `blending.md` gets
  one line.

### D4. Validator additions

- `references/form-dimensions.md` exists.
- `references/forms/` has exactly 6 `.md`.
- Every form under `## Voices` → **Forms** is backed by a file.
- `form-dimensions` is added to the required top-level `references/` set (from v3: all
  required present, no unexpected extras beyond generated `voices.md`).
- `build_index.sh` now includes `forms/`; `voices.md` regenerated.

### D — files touched

`superwriter/references/form-dimensions.md` (new), `superwriter/references/forms/*.md` (6
new), `superwriter/SKILL.md`, `superwriter/references/blending.md`, `scripts/build_index.sh`,
`scripts/validate_skill.sh`, `superwriter/references/voices.md` (regenerated), `README.md`.

### D — verification

- Validator passes; `references/` top-level set is `craft-dimensions`, `transform`,
  `analysis`, `blending`, `form-dimensions`, plus generated `voices.md`.
- `voices.md` up to date.
- Worst-case footprint for a form request (`SKILL.md` + `craft-dimensions.md` +
  `form-dimensions.md` + largest form profile) ≤ 10 KB.
- Read-through: a sonnet request produces 14 lines, a volta near line 9, no filler; a haiku
  request produces a cut, not a syllable-count exercise.

## Sub-project C — Opt-in micro-examples → v5

One original exemplar per voice, loaded only on request. Zero normal-path cost.

### C1. Structure

`references/examples/<voice>.md` — one per author, register, and form. At v5: 12 + 6 + 6 =
**24 files**. Each file:

- one original passage of ≈ 40–70 words in the voice, then
- a single line: `Shows: <the two or three dimensions this demonstrates>`.

Where a before/after is clearer than a standalone passage (e.g. `plain-english`,
`heroic-couplet`), use a ≈ 2-line source plus its rendered version instead.

**Hard rule**, stated in the authoring guidance and checked in review: no passage may
reproduce or closely paraphrase the actual author's writing. Every example is newly
composed for this repo.

### C2. Loading

- Loaded only when the user asks: `/superwriter <voice> --example`, or a natural request
  ("show me an example first", "what does Woolf mode look like?").
- `SKILL.md` routing row: `references/examples/<name>.md | user asks to see an example`.
- `--example` added to the documented grammar.
- Zero per-request cost on normal generate/transform.

### C3. Validator additions

- `references/examples/` contains exactly one `.md` per profile across
  `authors | registers | forms`, enforced **both ways**: no orphan example, no profile
  without an example.
- Shape check: each example file has a non-empty passage and a `Shows:` line.

### C — files touched

`superwriter/references/examples/*.md` (24 new), `superwriter/SKILL.md` (routing row,
`--example` grammar), `scripts/validate_skill.sh`, `README.md`.

### C — risk & mitigation

These are exemplars; a weak example is worse than none. The implementation plan treats each
example as an individually reviewed unit, not a bulk generation. Request code review on the
full batch before merge.

### C — verification

- Validator passes; 1:1 coverage holds.
- Spot-check 5 examples against the real authors for accidental paraphrase.
- Normal-path footprint unchanged from v4 (examples never load unless asked).

## Sub-project B — `analyze` → reusable profile → v6

Closes the loop: profile your own writing, then write *in* it.

### B1. Command

- `/superwriter analyze` — unchanged; describes the writing.
- `/superwriter analyze as <name>` — new; same analysis, output is a profile file.

### B2. Output

A profile in the exact `authors/` format:

- `# <name>` — the user's chosen label.
- `**Furthest from neutral:** <2–3 dimensions>` — where the sample sits furthest from neutral.
- the ten craft-dimension bullets, fixed order, each stating the sample's position; where a
  dimension is unremarkable, keep the bullet and write "near neutral" (parallel structure).
- `**Writing it:** …` closing on a caricature-failure line **derived from the user's own
  overuse patterns** — e.g. "every paragraph opens on a subordinate clause; vary the
  openings," "em-dashes do all the work the syntax should."

Then a short install block (not part of the profile file):

```
Save as superwriter/references/custom/<name>.md, add "<name>" under
## Voices → Custom in SKILL.md, run scripts/build_index.sh, repackage.
```

### B3. Statelessness / the custom slot

- New `references/custom/` directory. Ships containing only `README.md` (explains the slot)
  and `.gitkeep`. Tracked in-repo — a user maintaining their own fork wants their profiles
  versioned — but empty of profiles on release.
- The skill and validator treat any `custom/*.md` (other than `README.md`) as an
  author-equivalent profile.
- `SKILL.md` `## Voices` documents a **Custom** category: "profiles you generated with
  `analyze as`; `/superwriter <your-name>` resolves here."
- Routing order for `/superwriter <name>`: `authors/` → `registers/` → `forms/` → `custom/`.

### B4. Standing rule

Added to `analysis.md` and `SKILL.md` standing rules:

> `analyze as` builds a profile only from the user's own writing. Decline to build a named
> profile for a third party from a supplied sample — this route captures your own voice, not
> new named authors the roster deliberately omits.

### B5. Validator additions

- `references/custom/` exists and contains `README.md`.
- Any `custom/*.md` other than `README.md` passes the same shape check as `authors/`.
- `build_index.sh` includes `custom/` profiles when present; `voices.md` regenerated.

### B — files touched

`superwriter/references/analysis.md`, `superwriter/references/custom/README.md` (new),
`superwriter/SKILL.md`, `scripts/build_index.sh`, `scripts/validate_skill.sh`,
`README.md` (new "Write in your own voice" section).

### B — verification

- Validator passes with `custom/` empty (README only).
- Manual: run `analyze as testvoice` on a sample; the emitted file passes
  `validate_skill.sh`'s shape check when dropped into `custom/`; `build_index.sh` picks it
  up; `/superwriter testvoice` resolves.
- Standing-rule check: a request to `analyze as Hemingway` from a pasted passage is declined.

## Cross-cutting

### Validator evolution (end state after v6)

`validate_skill.sh` checks, each as an independent labelled block:

- frontmatter: exactly two keys (`name`, `description`), `name: superwriter`, one-line
  description, no blank line before the closing `---`;
- `references/` top-level `.md`: all required files present — `craft-dimensions`,
  `transform`, `analysis`, `blending` (plus `form-dimensions` from v4) — and no top-level
  `.md` outside that set except the generated `voices.md` (added v3);
- `authors/` = 12; `registers/` = 6; `forms/` = 6 (v4+);
- `examples/` 1:1 with profiles across `authors|registers|forms` (v5+);
- `custom/` present with `README.md`; any other `custom/*.md` passes author shape (v6+);
- every voice under `## Voices` in `SKILL.md` backed by a file;
- `references/voices.md` equals `scripts/build_index.sh` output.

### README

Each sub-project updates its own README sections in its own PR. No separate docs PR.

### Release process

Unchanged: PR → CI green → squash-merge → `git tag vN && git push origin vN` → release
workflow attaches `superwriter.skill`.

## Locked decisions

- Four PRs / releases, order **A → D → C → B** (v3 → v6).
- Forms get their own dimension file, not an extension of `craft-dimensions.md`.
- `voices.md` is generated and CI-verified, never hand-maintained.
- Examples are 1:1 with profiles and fully opt-in (`--example`).
- Custom profiles are tracked in-repo but ship empty; no runtime file writes.
- `analyze as` is restricted to the user's own writing.

## Out of scope

- LLM-graded eval harness — revisit after v6.
- Additional authors or registers beyond the current roster.
- Non-English literary traditions.
- Any runtime persistence or skill self-modification.
