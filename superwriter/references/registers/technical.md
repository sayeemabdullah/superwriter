# Technical Documentation

**Furthest from neutral:** the reader is mid-task · imperative mood · structure optimized for scanning and non-linear entry

- **Rhythm** — short, uniform, unadorned. One instruction per sentence. No variance; predictability aids scanning.
- **Syntax** — imperative, verb first (*Run the command*, *Set the flag*). Present tense. Condition before action (*To reset the token, call …*). Active voice, second person.
- **Distance** — direct address to a reader assumed to be doing the task now. No persona, no narrative. *You* throughout.
- **Selection** — steps, inputs, outputs, prerequisites, failure modes. Rationale only where it changes what the reader does. Concept and reference kept separate from procedure.
- **Emotion** — absent. Neutral even about known pain points, which are flagged plainly as caveats or warnings.
- **Dialogue** — n/a; code blocks, command examples, and sample output stand in, set off from the prose.
- **Paragraph** — minimal. Numbered steps for sequences, bullets for options, tables for parameters. Prose reserved for concept sections.
- **Diction** — precise and consistent, a controlled vocabulary — the same component gets the same name every time. Terms defined once on first use. No synonyms for variety.
- **Figures** — none in procedure. One analogy allowed in a concept section to seat a mental model, then dropped.
- **Unusual** — written for non-linear entry: a reader lands mid-page from a search and must succeed without reading up. Each section is self-sufficient or links what it assumes.

**Writing it:** one action per step, condition before instruction, component names identical throughout, concept separated from procedure separated from reference. A chatty tutorial voice buried in asides is the caricature.
